#### 4. Measures We ALREADY Implement

These are live in the codebase today and can be stated as factual safeguards.

#### Security

- No passwords stored. Authentication is phone + one-time-password (OTP) + signed tokens (JWT). Eliminates password-breach risk.
- OTP protections: rate-limited (max 3 requests / 5 minutes per number), brute-force capped (max 5 verification attempts), time-limited expiry; OTP values are never written to logs.
- Token security: short-lived access tokens (1 hour), separate refresh (30 days) and registration (15 minutes) tokens, each signed with an independent secret; the app refuses to start if any signing secret is missing or too weak.
- Encryption in transit: all traffic over HTTPS/TLS; database connections over private, encrypted channels.
- Encryption at rest: database (MongoDB Atlas) and file storage (AWS S3) are encrypted at rest; uploaded files sit in a private bucket reachable only via short-lived signed links.
- Secrets management: all credentials (database, payment, messaging, token secrets) held in AWS Secrets Manager, injected at runtime — none hard-coded.
- Role-based access control: a permission matrix governs what each of the 7 user roles may do.
- Production safety guards: the app refuses to run in production with insecure test modes enabled (test-OTP bypass, console-only notifications, manual/fake payments, or listing auto-approval are all blocked in production); error messages are sanitized in production to avoid leaking internals.

#### Privacy by Design

- Data minimization at registration (only phone + name required universally).
- No card data retained (Razorpay handles it).
- Contact masking: users' contact details are not exposed by default; they are revealed only through a controlled "contact unlock" flow (subject to free limits or subscription), and Keydemand-posted listings are anonymized as "Posted by Keydemand".
- Image-visibility control: sensitive listing images are hidden by default and shown only to the owner, Keydemand, or users explicitly granted access.
- Privacy-first access ordering: the API denies access (403) before confirming a resource exists (404), so it never leaks the existence of another user's data to unauthorized callers.
- Consent gating of notifications: WhatsApp messages are sent only when the user's opt-in flag and the relevant notification preference are enabled.

#### Data Lifecycle

- Automatic purging: behavioural activity logs and in-app notifications auto-delete after 90 days.
- Auto-expiry: demands and enquiries auto-expire (e.g., enquiries after 72 hours) and are then retired.
- Soft-delete + audit trail: records are soft-deleted with referential integrity preserved; an immutable audit log captures significant admin/user actions (who did what, when).

#### Data-Subject Controls (partial, see §5 for gaps)

- Account deactivation / reactivation (reversible) by the user.
- Account deletion request workflow with reason capture and status tracking.
- Admin suspension with reason + audit trail.
- Marketing opt-in toggle editable by the user (WhatsApp).

#### 6. India DPDP Act 2023 — Specific Points

- Consent notice ("itemised notice") at or before collection, in clear language, with the option to access in English / scheduled Indian languages.
- Grievance Officer must be appointed and contactable; user-facing grievance redressal with response timelines.
- Consent withdrawal as easy as giving consent; Consent Manager interoperability readiness.
- Verifiable parental consent for users below 18; no behavioural tracking/targeted advertising to minors.
- Data-principal rights: access, correction, erasure, grievance, nomination.
- Data-retention limitation: erase personal data once the purpose is served / consent withdrawn (drives the automated-erasure item).
- Significant Data Fiduciary obligations may apply at scale (DPIA, independent audit) — assess as user volume grows.

#### 7. EU GDPR — Specific Points

- Lawful basis documented per processing purpose (contract, consent, legitimate interest) — see §2.
- Data-subject request (DSR) workflow for access, rectification, erasure, portability, objection, restriction.
- Standard Contractual Clauses for personal data transferred to India, plus a transfer-impact assessment.
- Data Protection Impact Assessment (DPIA) for large-scale processing / behavioural profiling.
- EU representative (Art. 27) if Keydemand has no EU establishment but targets EU data subjects.
